# 0079. Meaning of the NameSpec and RootSpec fields in names.ts

Status: Accepted
Applies to: `src/registry/names.ts`

## Context

src/registry/names.ts is the registry for the semantic phase. Each row answers one question: for this name and this receiver, in which positions is the name legal, and what MQL does each position produce? The emitter reads only the row, so every fact must be a field with one clear meaning.

## Decision

Key space. The key is the name exactly as the user types it. `sort` and `$sort` are two keys, a JavaScript name and a MongoDB name. The audit at the foot of the file (`_everyKeyMatchesItsKind`) makes a compile error when a name sits under the key of the other kind. These kinds share the key space: `root` (`$`, `$$`, `Math`: a receiver that a binder attaches a name to), `name` (a JavaScript name), `mongo` (anything MongoDB names; "operator" and "stage" are positions, not kinds, because `$count` is both) and `global` (callable by name, with no receiver).
Root fields. `returns` is the type of the value the root reads as. `$` alone is the whole document; MEASURED `{ $type: "$$ROOT" }` is `"object"`. A namespace (`Math`) and a context reference (`$$`) give no value and state none. A root has the same cells as every other entry, and its cells hold its messages. Without them, a context reference could state `where: ["stream"]` in one place. It could state a different message in another place. Nothing would catch the disagreement. `assert(cond);` is receiver-less and statement-only, so its stream and statement cells hold it.
NameSpec fields:
- `on`: the compiler probes the receiver families in declaration order, so the precedence is visible.
- `elements: "scalar"`: an element that is an array gives MongoDB text (`$toString` of `[1, 2]` is `"[1,2]"`), not the JavaScript text `"1,2"`. So the compiler refuses a receiver that provably holds arrays, for example a literal of literals or `.partition(…)`. The refusal names two rewrites: flatten the array, or map each inner array to a string. `elements: <kind>` says that every element must have that kind. HR7 reads it. The compiler refuses a receiver that it proves holds an element of another kind, even where the server accepts the MQL. An array of unknown elements passes.
- `picksOne`: on a stream this method picks one document (`.find`). On another collection it runs the stream cell of the named row (`filter`) plus `$limit: 1`. It takes the shorthands of that row and yields a document (see src/compiler/emit/join.ts).
- `streamBody: "document"`: the stream cell replaces the document (`.map`), so the callback body must be a document. A `.map` to a value on another collection reads the joined array as a value instead.
- `collapses`: the stream cell folds the whole stream into one document (`countBy`, `keyBy`, `groupBy`). On another collection the joined array holds that one document, which is the value, so the read unwraps it.
- `sibling`: the way forward when the compiler proves that the receiver is a family the row does not take. One sentence per family; for example `.length()` on an array names `.size()`. The refusal in src/compiler/emit/errors.ts puts the sentence after its head, in place of the generic family hint.
- `renamedTo`: the method that JSMQL writes for this name. The row refuses in every position and names the method. A close typo gets the method as its suggestion, so the user reaches a working method in one step. Build such a row with `renamed(…)`. The parser accepts the name so that JSMQL can refuse it with a message. `reason` says why `to` is the spelling of `from`, and `also` adds one sentence for the row.
- `restoresDocuments`: the stream cell gives every document back as it arrived, fewer and unchanged. `.uniq()` groups on a key and does `$replaceWith` on the kept document, so its `$group` replaces nothing that a later link can see. The unwound element of an earlier `.flatMap` and each `let` field stay. Without this fact, a `$replaceWith` in the cell reads as a changed document. Every row whose stream cell keeps the first document per key states it.
- `elementOnly`: the stream cell works on the element, not the document (`.difference(list)` keeps the unwound values that are not in `list`). On a stream whose element is the document (no earlier `.flatMap`), the link is not a stream link. At the top of a pipeline the compiler refuses it with `why`. In a join the compiler reads the joined array as a value. `when: "bare"` is for a row whose zero-argument call alone reads the element: `.sortBy()` sorts by the values, but `.sortBy("k")` is a stream link on any stream.
- `unions`: on the stream the method adds documents with one `$unionWith` per source (`push` as a statement, `concat` as a link). `mergesInto`: on a collection reference the method writes the documents into that collection with `$merge`, which keeps the existing documents (`$$$.<coll>.concat(<documents>);`). It is a separate fact because it names a different stage on a different receiver.
- `iterateeSlots`: the argument slots that take an iteratee, per receiver family, because the slot layout depends on the receiver (`$.items.groupBy(fn)` versus `Object.groupBy($.items, fn)`). Only these slots accept a short spelling that the compiler rewrites into an arrow. Other slots take the same spellings with other meanings: `.filter({ f: 1 })` is a matcher, `.toSorted({ f: 1 })` is a direction, `.pick(["a", "b"])` is a list of field names. A rewrite that reads the shape of the argument would turn a sort into a matcher with no warning. `.sortBy()` refuses the object form for this reason. The field is not on `Arity`, because an `Arity` requires a `sig` and a count, and a spelling has no count.
- `blockBody`: absent means `"javascript"` for every name but one. The compiler refuses a stage inside a JavaScript block and gives a rewrite hint. `$$ = $$.map(d => { $sort({a:1}); })` is refused; `$$ = $$.aggregate(o => { $sort({a:1}); })` gives `[{ "$sort": { "a": 1 } }]`.
Mutator fields:
- `immutableTwin`: a name with the same meaning and the same arguments that mutates nothing, only on a mutator (`$.a.sort(k);` becomes `$.a = $.a.toSorted(k)`). "Same arguments" is the whole test. `.pop()` has no twin. `.toSpliced(-1, 1)` computes the same array, but the rewrite must invent the arguments. The MQL is 1.5 times the size of the direct lowering (4.4 times for `.shift()`). A mutator with no twin lowers directly.
- `asArrayLiteral`: the mutation as an array literal, which is a shape, not a name. `push` is "receiver, then arguments" (`$.a = [...$.a, 9]`), and `unshift` is "arguments, then receiver". The field spells the order in words, because "start" or "end" leaves the reader to ask "of what?".
- `mutatorForm`: the write form of a mutator with no same-argument twin (`.pop()`, `.fill()`). It gives the JSMQL expression by argument count, with `_r` for the receiver and `_0`… for the arguments. See `MutatorForm`.

## Consequences

A new row states each fact as a field, never as a special case in the emitter. A new mutator states `immutableTwin` only when the arguments match exactly.
