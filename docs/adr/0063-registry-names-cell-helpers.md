# 0063. Shared cell helpers in names.ts and the null rules they obey

Status: Accepted
Applies to: `src/registry/names.ts`

## Context

Many method cells share helpers for null handling, list arguments, query clauses and lodash semantics. HR5 wraps a receiver before a cell sees it (`dispatchOn` in src/compiler/emit/lower.ts), but not an argument. Several server operators abort the command on null.

## Decision

Null and presence:
- `nullOr` gives null for a null or missing receiver and the body elsewhere. Under a dot, HR5 reads the receiver as its safe value first, so the receiver is `present` and the test drops out. The test stays where no safe value applies, for example in a dispatch branch that admits null. `$strLenCP` aborts the command on null, so a cell must not run its body on a receiver that can be null. The body runs on a proven receiver and needs no guard. A path is cheap to read twice; the helper binds any other value once. Callers of `padded` pass a receiver that `nullOr` proved, so the binding takes it as it is.
- `arrayOrEmpty`: a reader over a missing field answers null, not `[]`. MEASURED: `$map`, `$filter`, `$setUnion`, `$slice`, `$sortArray` and `$reduce` answer null, and `$in` and `$size` refuse it. A cell calls this helper for a list argument. A literal passes unchanged. A `?.` read already gives `{ $ifNull: ["$a.b", null] }`, so one `$ifNull` turns it into `[]`. `listArgument` skips the guard when the proof shows the list present (`$.z.union($.a.uniq())`).
- `pairsOfObject`: MEASURED, `$objectToArray` answers null on a missing field and `$arrayToObject` passes the null on. HR5 reads a missing object as `{}` under a dot, so `_.pick(undefined, …)` and `({}).keys()` answer as on the empty object. The guard here covers an object argument.
- `pairsRead` (`.keys()`, `.values()`, `.entries()`): one body serves both cells of a row, because the object family and an unproven family must give the same MQL, and two copies drift. Its `in` body reads the default `$$this`, because the body is fixed text with no developer expression.
- `lastIndexOfArray`: one function serves the array family and an unproven family, because both must give the same MQL. A cell that read `present` would answer differently inside the family dispatch and force a needless `$switch`. So the size guard is unconditional: `$size` aborts the command on a missing array, where `$indexOfArray` and `$subtract` answer null.
- `safeOfBounds` and `safeBound`: `.clamp()` and `.inRange()` take a number or a date. `dispatchOn` wraps the receiver of a one-family row and of a proven family on its own. For any other receiver the cell states the wrap, and the kind of the bounds picks the safe value: 0, or the epoch when a bound is a date. `sameAsNull` says that the safe value gives the answer that null gives, so the wrap adds nothing.
- `mayHold`: two constant bounds of one kind give the answer at compile time. A number sorts before every date, so 0 is never in a range of two dates, and the epoch is never in a range of two numbers.
- `orderedBounds`: `.inRange()` accepts its bounds in either order. The expression form orders them at run time with `$min` and `$max`. A query clause has no such operator, so the helper orders two constant bounds of the same kind. A number against a date does not compare, and the row keeps the expression fallback.
Query clauses:
- `fieldClause`: a query operator call such as `$gt($.a, 1)` gives the query clause `{ a: { $gt: 1 } }` when the first argument is a field path and the second a constant. Otherwise it gives null, and the expression form takes the call. The raw spelling keeps MongoDB's reading and adds no own-value clause.
- `logicalList`: each predicate becomes its own filter. MEASURED: the server refuses `find({ $and: [] })`, but `{ $expr: { $and: [] } }` answers true, as `[].every(…)` does. So an empty list gives null and goes to the value road. `norList` is total: `$nor` is filter-only, and the row's `nonEmpty` fact refuses the empty list before the cell runs.
- `matchesEmpty` decides whether a regex matches `""` on the server. A dot reads a missing string as `""` (HR5), so the answer decides whether `.match()` matches a missing field. The helper runs the pattern on `""` in JavaScript. The PCRE anchors `\A`, `\z`, `\Z` and `\G` match on `""`, but JavaScript reads each as a letter. So each one outside a character class becomes an empty group first. All other escapes and classes stay as written.
Arrays and objects:
- `keepFirstPer`: one document per distinct key, the first kept; it gives the stages of every `restoresDocuments` row. A key that is the whole document needs no second copy, because the group key is the first document itself. MEASURED: among documents that compare equal, the key keeps the first, as `$first` does. An int and a double of one value compare equal, and so do "A" and "a" under a case-insensitive collation.
- `concatOperand`: JavaScript `concat` splices an array argument and adds any other argument as one element. `$concatArrays` takes arrays only and answers null for a null operand. So the proof of the argument picks the shape: a present array as written; an array or null as `{ $ifNull: ["$b", [null]] }`; a non-array as `[5]`; an unknown value as `{ $cond: [{ $isArray: "$b" }, "$b", ["$b"]] }`. MongoDB has no `undefined`, so a missing argument adds a null element. MEASURED with `{ $concatArrays: [[1], <operand>] }`: `[1, 2]` for `b: [2]`, `[1, 5]` for `b: 5`, `[1, "xy"]` for `b: "xy"`, and `[1, null]` for null and for no `b`. A path is cheap to read three times; the helper binds any other value once.
- `concatSpread`: each element of `...x` follows the `concatOperand` rule through a `$reduce`. `list` is the lowering of `[...x]`, so a missing `x` spreads nothing. An `x` whose elements are proven non-arrays splices as it is.
- `merged` (`.assign()`): one `$mergeObjects`. A spread argument is a list of sources, and a plain argument is one source object. The desugar pass packs spread arguments (`packed`), so the cell sees the form. An empty object receiver adds nothing and the cell leaves it out where the sources stay objects: `({}).assign(...$.docs)` gives `{ $mergeObjects: "$docs" }`, and `({}).assign($.a, $.b)` gives `{ $mergeObjects: ["$a", "$b"] }`. One plain source keeps the `{}`, because the one-operand form would merge an array source. MEASURED: `{ $mergeObjects: [{}, "$o"] }` gives `o`, and `{}` for a missing `o`; `{ $mergeObjects: null }` is `{}`, so a list alone takes no guard. A list after a real receiver takes the HR5 guard of the array literal, because MEASURED `{ $mergeObjects: { $concatArrays: [["$o"], "$nope"] } }` is `{}` and loses the receiver.
- `spelledKeys`: the `arrayOf` rule holds every spelled element of a `.pick()` or `.omit()` list to a field name, so a list of string literals is a list of names. Anything else (a field path, a spread, a computed element) is a run-time value, and the row reads the object's own keys.
Lodash semantics:
- `padded`: `.padStart`, `.padEnd` and `.pad` take a constant length of 1 or more and a pad of one ASCII character; the row's `constant` and `slotRange` rules guarantee the length. One `$reduce` adds the pad once per missing character. Its `$range` counts down from the length to the string length. MEASURED: the range is empty when the string is long enough. `.pad` adds at the end on the first step, then at the start, so the end takes the odd character, as `_.pad` does. A step whose `$$this` has the parity of the length adds at the end.
- `randomOf` (`_.random(lower, upper)`): the receiver is `lower`. With no argument the receiver is `upper` and `lower` is 0. The bounds swap when `lower` is larger. Two whole bounds give a whole number with both ends included; any other pair gives a fraction. A constant pair decides the form at compile time, and the server tests a run-time pair. A missing bound reads as 0. `(1).random(6)` gives `{ $add: [1, { $floor: { $multiply: [{ $rand: {} }, 6] } }] }`.
- `RANGE_ARGS` holds integer slots, because `$range` refuses a zero step and a fractional bound. In `rangeOf` the step reads each bound twice, so a computed bound binds once.

## Consequences

A new cell that reads a list or object argument must use these helpers. Keep one body for the cells of a family and the unproven case, so that the MQL cannot drift.
