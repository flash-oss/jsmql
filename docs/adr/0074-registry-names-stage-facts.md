# 0074. Stage facts on a mongo row, and the per-stage server facts behind them

Status: Accepted
Applies to: `src/registry/names.ts`

## Context

A stage body can mix positions, and the server reads each slot in its own way. The compiler needs to know the position of each path in a body, which slots the server evaluates, and what the stage does to the document.

## Decision

`StageFacts`: a stage row states `bodyPositions`, `document` and `evaluates`. A row that is not a stage states none of the three. They are one type, so they cannot come apart.
`bodyPositions` maps a dotted path in the body to a position. The path vocabulary and the layouts are in [position-pass.md § A stage body is laid out by its own row](../specs/position-pass.md#a-stage-body-is-laid-out-by-its-own-row). Split the sentence at the comma before 'because'. Start the second sentence with: A flat key list could not reach the pipelines `*` segment, because a flat key list could not reach the pipelines of `$rankFusion`, which sit two levels down under the developer's names. The row states the map and never derives it, because only the row knows how the body mixes positions. The `_id` of `$group` is an expression, but every other key is an accumulator. MEASURED: `{ $group: { _id: { $sum: ["$x","$y"] } } }` runs, and `{ $group: { _id: null, s: { $sum: ["$x","$y"] } } }` fails because the accumulator takes one operand. `$geoNear.query` and `$graphLookup.restrictSearchWithMatch` refuse a top-level `$eq`, because a query slot is not an expression slot. MEASURED: `{ $geoNear: { …, query: { $expr: { $eq: ["$k","a"] } } } }` runs. A body position with no entry makes the compiler emit invalid MQL in each of these slots. A slot with two shapes states both, because the server accepts both: `$merge.whenMatched` takes a word or an update pipeline.
A row states `evaluates` for each stage, because the server evaluates only some slots of a body as expressions, and reads the others as written. HR1's gate for a run-time value reads this fact. In an evaluated slot, a value that reads as MQL takes `$literal`. In a slot read as written, the compiler refuses such a value. MEASURED with `$literal`: `$group._id`, `$replaceWith` and `$bucket.default` accept it and give the literal value. `$unwind` reads it as an unknown option, `$lookup.from` reads it as an unknown field, and `$sort` accepts no expression other than `$meta`.
A row states `document` (a `DocumentEffect`) for each stage from a measurement. MEASURED for a `let` binding: after `$group` the binding has no value, and the compiler refuses a read. After `{ $project: { x: 0 } }` it survives, because an exclusion keeps the rest, and under `{ $project: { x: 1 } }` it goes away. After `$sort` it survives. After `$unionWith` the stream holds another collection's documents, so its `document` is `"unknown"`. `$redact` keeps every field that its expression does not name, so its `document` is `"keeps"`; MEASURED `{ $redact: "$KEEP" }` runs.
`preservesCount`: the stage changes neither the count of the stream nor the fields, so a count that a field holds stays valid. Only a few stages state it, because the safe answer is "no": a stale count is a bug, and a new count is always correct. MEASURED: `$sort` keeps both. `$unwind` keeps the fields but emits one document per element, so the count is stale. `$group` drops the fields. The stream handle of a body reads this fact, and a body that runs a stage without it cannot carry a count.
`takesLet`: the body takes a `let` document whose variables its sub-pipeline reads. A read of the outer document inside the body reaches the server through this `let` (the join road). `$unionWith` has no `let`, so it cannot carry such a read. `pipelineOver: "foreign"`: the sub-pipeline runs over another collection. Inside it `$.x` still means the outer document (HR4), and the server reaches it only through the `let`. A binding that a field carries is not there at all. `$facet` runs over the same documents and states nothing.
`statementBody` says what a body slot with position `statement` holds. Every row with such a slot states it, and test/registry-agrees.test.ts fails a row that forgets. `"pipeline"` is a pipeline of its own, with its own first position, so the compiler judges a stage inside it by its own placement. A name list is an update spec, which is no pipeline: there is no first place, and only the listed stages run. MEASURED on the project server, one stage per run with a valid body: the stages in the `$merge` list run in an update, and the server refuses every other stage. The compiler refuses a stage that the language gains later until the list names it, which is the safe default and the server's own answer.
`bansNested` lists the stages that the server refuses anywhere inside the bodies of this container, at any depth. `forbiddenIn` is the direct reading, the stage as a step of that body. MEASURED for `$facet`: `$documents` reaches through a `$unionWith` that a `$lookup` or another `$unionWith` accepts, and both run. A facet branch refuses it at any depth. A `$unionWith` that names a collection is fine in a branch, so the ban is the literal-documents form alone.
`placement` holds the words of a placement refusal where the generic sentence is wrong. `first` replaces the generic reason for a first place (that the stage makes the starting documents). `container` replaces the generic advice to move the stage to the outer pipeline. A name with no place in a collection pipeline needs the spelling that does the same job. The refusal never sends the reader to a place where the server also refuses. For `$documents`: MEASURED, it fails on a collection aggregation and needs a database or cluster aggregation. The server takes it only inside a `$unionWith` that names no collection, and JSMQL writes that shape from `$$.push(…)`. So its `container` text names the sugar. The `$$ = [ … ]` and `$$$.<coll>.push(…)` sugars are JSMQL code. They read this row's element rule (`documentsStages` in src/compiler/emit/statement.ts), so a written element that is not a document has no MQL. A raw `$documents(…)` call is the developer's own MQL, and the compiler does not check it.
`$search` and `$searchMeta` run only on Atlas, so the project server cannot measure them. Their bodies are a language of their own and pass through, so `evaluates` is empty.

## Consequences

A new stage row must state `bodyPositions`, `document` and `evaluates` from a measurement. A new update-capable stage stays refused until the `$merge` `statementBody` list names it.
