## 2026-10-17 — feat: `.slice()` and `.concat()` state `passesNull`

The developer confirmed that `.slice()` and `.concat()` are array methods only. A string
takes `.substring()` or `.substr()` for a part. A string takes `+` to join. Both rows
already list `array` and `stream`. A proven string receiver gets the refusal that names
the string form. The entry [feat: 91 more rows state `passesNull`](#2026-10-17--feat-91-more-rows-state-passesnull)
below says that the two rows take two receiver families. The earlier entry is wrong. Both
rows now state `passesNull`. The mongod server gives `null` for a missing receiver and for
a `null` receiver. It also gives `null` with a negative start:

```
$.a?.slice(1)       → { $let: { vars: { jsmqlArr: "$a" }, in: { $slice: [ … ] } } }   (no $cond)
$.a?.concat($.b)    → { $concatArrays: ["$a", { $cond: [{ $isArray: "$b" }, "$b", ["$b"]] }] }
"abc".slice(1)      ✗ a string takes .substring(start, end)
```

## 2026-10-17 — feat: 91 more rows state `passesNull`

A probe set `passesNull` on each method row in turn, and compiled `$.nope?.m(…)` from the
row's sample call. It ran the call on mongod over a missing and a `null` receiver. Each row
whose bare call gave `null` both times, with no server error, now states the fact. A `?.`
before such a call emits no null test. Only a row with one receiver family takes the
fact. A row that reads two families (`.slice()`, `.concat()`, `.indexOf()`) dispatches on
the type at run time, and one sample proves only one branch. The rows are the string
trims and replacements, most array methods, the object readers and the date methods.

```
$.name?.trim()       → { $trim: { input: "$name" } }
$.a?.uniq()          → { $setUnion: "$a" }
$.d?.getFullYear()   → { $year: "$d" }
$.a?.size()          → { $cond: [{ $lte: ["$a", null] }, null, { $size: "$a" }] }   ($size fails on null)
```

The table in [test/compiler-methods.test.ts](../../test/compiler-methods.test.ts)
measures each row over both receivers.

## 2026-10-17 — feat: a `?.` read takes no `$ifNull` where the consumer passes null

A `?.` read with no call after it is `{ $ifNull: [x, null] }`, so a missing value reads
as `null`. Many consumers give the same answer for missing and for `null`, and the wrap
adds nothing there. The productions of `+` on numbers, `-`, `*`, `/`, `%`, `**`, `-x` and
`??` now state `passesNull`. A test in
[test/compiler-methods.test.ts](../../test/compiler-methods.test.ts) measures each one on
mongod. `== null`, `!= null` and every truth test read the operand the same way.
`== null` is now the short null test itself:

```
$.b?.c ** 2       → { $pow: ["$b.c", 2] }                 (was { $pow: [{ $ifNull: ["$b.c", null] }, 2] })
$.b?.c ?? 0       → { $ifNull: ["$b.c", 0] }
$.b?.c == null    → { $lte: ["$b.c", null] }              (was a $type test against "null" and "missing")
$.b?.c ? 1 : 2    → { $cond: [{ $and: [{ $gt: ["$b.c", null] }, …] }, 1, 2] }
$.b?.c === 1      → { $eq: [{ $ifNull: ["$b.c", null] }, 1] }   (kept: $eq tells missing from null)
```

The comparisons keep the wrap, because `{ $eq: ["$nope", null] }` is false and
`{ $eq: [null, null] }` is true. The `.join()` element test uses the short null test too.

## 2026-10-17 — feat: a shorter null test, and `$cond` in its array form

The developer asked for the shortest MQL of `?.`. Two shapes in every program get
shorter. The null test of `?.` and of a string method is `{ $lte: [x, null] }` in place
of `{ $eq: [{ $ifNull: [x, null] }, null] }`. Its negation in the JavaScript truthiness
check is `{ $gt: [x, null] }`. Null sorts below every other value but `MinKey`, so one
comparison covers missing and null. The mongod server gave the same answer for both
tests on a missing value, `null`, `0`, `""`, `false`, `[]` and `{}`. Only a `MinKey` value
reads as null now, and the developer accepts that.

The compiler writes each `$cond` in the array form `[if, then, else]`, in place of the
object `{ if, then, else }`. The developer's own `$cond(…)` call keeps the object form
that HR2 gives it, because it is the developer's MQL.

```
$.s?.trim()     → { $cond: [{ $lte: ["$s", null] }, null, { $trim: { input: "$s" } }] }
$.a ? 1 : 2     → { $cond: [{ $and: [{ $gt: ["$a", null] }, { $ne: ["$a", false] }, …] }, 1, 2] }
```

## 2026-10-17 — feat: `.random()` is lodash's `_.random` on a number

`x.random()` gives a number from 0 to `x`. `x.random(y)` gives a number between `x` and
`y`. Both match lodash's `_.random(x)` and `_.random(x, y)`. The bounds swap when the first is larger.
lodash gives a whole number, both ends included, when both bounds are whole, and a
fractional number otherwise. The developer picked that rule, tested at run time. Two constant
bounds decide the form at compile time. For bounds from a document, the MQL holds a `$let` of
the two ends, and the server runs a `$cond` whole-number test. A missing bound reads as `0`,
as lodash reads it, so the row states `nullReceiverAs: 0`.

```
(1).random(6)       → { $add: [1, { $floor: { $multiply: [{ $rand: {} }, 6] } }] }
(5).random()        → { $floor: { $multiply: [{ $rand: {} }, 6] } }
(1.5).random(2)     → { $add: [1.5, { $multiply: [{ $rand: {} }, 0.5] }] }
$.a.random($.b)     → { $let: { vars: { jsmqlLo: { $min: […] }, jsmqlHi: { $max: […] } }, in: { $cond: … } } }
```

A test in [test/compiler-methods.test.ts](../../test/compiler-methods.test.ts) runs each
form 400 times on mongod. It checks the range, both whole ends, and the whole or
fractional answer. `Math.random()` stays `{ $rand: {} }`. JSMQL does not take lodash's
third argument, `floating`.

## 2026-10-17 — fix: `.sign()` gives 0 for a missing number

The developer decided that `.sign()` has a safe value. A missing or `null` number reads
as `0`, so its sign is `0`. This replaces the `null` answer of
[the number-methods entry](#2026-10-17--feat-the-number-methods-replace-the-math-members-that-take-a-value)
below. The row now states `nullReceiverAs: 0` in place of `passesNull`, as `.range()`
does. A `?.` keeps its `$cond`, so it gives `null`. The shape is shorter too:

```
$.x.sign()     → { $cmp: [{ $ifNull: ["$x", 0] }, 0] }        → 0 for {}
$.x?.sign()    → the $cond null test, then { $cmp: ["$x", 0] }  → null for {}
```

## 2026-10-17 — docs: one capability gets one spelling, and the shorter spelling wins

[docs/DEFERRED.md](../DEFERRED.md) §B records the rule behind the removal of the
`Object` statics and the `Math` members that take a value. A second spelling of one
capability makes each codebase pick one, and gives a reader two forms to learn. A
static stays when it is the shorter spelling, for example `Date.now()`, or when it has
no other spelling. `Object.groupBy` and `Set` are earlier cases of the rule. The §B row on the
escape-hatch spread now names the forms that take a list: `arr.max()`,
`({}).assign(...arr)` and the object spread. The developer-experience paragraph of
[CLAUDE.md](../../CLAUDE.md) does the same.

## 2026-10-17 — feat!: the number methods replace the `Math` members that take a value

The rule "one capability gets one spelling, and the shorter spelling wins" also covers
`Math`. Each member that takes a value now lives on the number receiver. The `Math`
cell of each row refuses the static and names the method. `Math.pow` names `**`,
and `Math.max` and `Math.min` name the array's `.max()` and `.min()`. `Math` keeps the
three members that take no value: `Math.random()`, `Math.PI` and `Math.E`.

```
Math.abs($.delta)        ✗ write $.delta.abs()
Math.pow($.b, 2)         ✗ write $.b ** 2
Math.max($.a, $.b)       ✗ write [$.a, $.b].max()
$.n.round()              → { $round: "$n" }                                  (was ["$n", 0])
$.n.floor(1)             → { $divide: [{ $floor: { $multiply: ["$n", 10] } }, 10] }
$.x.cbrt()               → { $multiply: [{ $cmp: ["$x", 0] }, { $pow: [{ $abs: "$x" }, 0.3333333333333333] }] }
$.x.sign()               → { $multiply: [{ $cmp: ["$x", 0] }, { $pow: ["$x", 0] }] }
$.x.log(10)              → { $log10: "$x" }
$.raw.trunc(2).log10()   → { $log10: { $trunc: ["$raw", 2] } }
```

`Math.sign($.x)` was `{ $cmp: ["$x", 0] }`, and the server gives `-1` for a missing
`x`. The new shape multiplies by `{ $pow: [x, 0] }`. That factor is `1` for a number and
`null` for a missing value. So `.sign()` gives `null` there, as the other arithmetic
methods do. The developer picked it over a `$cond`, because it is shorter. Because the
shape already gives `null` for `null`, the `.sign()` row states `passesNull` too, and
`$.x?.sign()` takes no `$cond`. The task planned `.sign()` without the fact. The guard
table wanted the same shape under `?.`, and the fact gives that shape. Each other
new number row states `passesNull`, and
[test/compiler-methods.test.ts](../../test/compiler-methods.test.ts) measures each one.

A constant precision of `.ceil(n)` and `.floor(n)` folds the scale (`10` in place of
`{ $pow: [10, 1] }`). The mongod server gives `10 ** p` for `-7 ≤ p ≤ 15`. The fold of
a constant moves to the number methods (`(3).abs()` is `3`), for the methods whose
answer IEEE-754 specifies. The reducer wrap reads `[acc, d.x].max()` as `$max`, and
the update document reads `$.n = [$.n, 3].min()` as `$min`. A bare `Math.floor` value
or callback (`$.a.map(Math.floor)`) answers with the row's refusal. A misspelled static
never suggests a refused member. The integer hint of `.range()` names `.ceil()` and
`.floor()`.

## 2026-10-17 — feat!: the receiver methods replace the `Object` statics

JSMQL had two spellings for each object reader: the JavaScript static and the method of
the receiver. The developer's rule is "one capability gets one spelling, and the shorter
spelling wins". The method is shorter in each case, so `Object.keys`, `Object.values`,
`Object.entries`, `Object.fromEntries` and `Object.assign` are no longer JSMQL names.
They still parse, and the `Object` cell of each row refuses the call and names the
method, as `Object.groupBy` does. The `Object` root row stays, because the refusal
needs the name to parse. A suggestion for a misspelled static never names a refused
static now (`lowersOn` in [src/compiler/rows.ts](../../src/compiler/rows.ts)).

```
Object.keys($.doc)           ✗ write $.doc.keys()
Object.assign(...$.docs)     ✗ write ({}).assign(...$.docs)
Object.assign($.f, $.x);     ✗ write $.f = { ...$.f, ...$.x };
({}).assign(...$.docs)       → { $mergeObjects: "$docs" }
({}).assign($.o)             → { $mergeObjects: ["$o"] }
$.a.assign(...$.docs)        → { $mergeObjects: { $concatArrays: [["$a"], { $ifNull: ["$docs", []] }] } }
$.o.keys()                   → { $map: { input: { $objectToArray: { $ifNull: ["$o", {}] } }, in: "$$this.k" } }
$.p.fromEntries()            → { $arrayToObject: { $map: { input: { $ifNull: ["$p", []] }, in: [{ $toString: { $first: "$$this" } }, { $arrayElemAt: ["$$this", 1] }] } } }
```

`.assign()` reads a spread argument as a list of sources and a plain argument as one
source. Before, `({}).assign(...$.docs)` emitted `{ $mergeObjects: [{}, "$docs"] }`, and
the server rejects that when `docs` is an array. An empty receiver is now dropped.
After a real receiver, a spread list takes the HR5 guard of the array literal. Without
it, the server answers `{}` for `{ $mergeObjects: { $concatArrays: [["$o"], "$nope"] } }`,
so the receiver is lost. The mongod server also merges `{ $mergeObjects: ["$docs"] }`
as one list, so `["$o"]` and `"$o"` give the same answer for one plain source.

`.assign()` writes nothing in place, so the desugar rule that turned
`Object.assign(t, …);` into a write is gone, with the `mutatesArgumentAt` row fact.
lodash's `_.assign` writes its target, so a lone `$.p.assign(…)` or `r.assign(…);` is
still a statement, and the statement cell refuses it and names the write back.
`.keys()`, `.values()`, `.entries()`, `.toPairs()` and `.fromEntries()` read `$$this`
in place of a minted name, because each `in` body is fixed compiler text. The fold
now folds the method forms on a constant: `({ a: 1 }).keys()` is `["a"]`.

## 2026-10-17 — feat: a `?.` before a call that gives null for null adds no test

A `?.` before a call stops the chain with a `$cond` null test. For some operators that
test adds nothing, because the operator gives `null` for a `null` operand on its own.
The mongod server gives `null` for `$max`, `$min`, `$round`, `$ceil`, `$floor`, and for
`$objectToArray` and `$arrayToObject` over a missing value. A new row fact,
`passesNull`, states this. `stoppedChain` in
[src/compiler/emit/lower.ts](../../src/compiler/emit/lower.ts) emits the calls alone
when each call after the `?.` states the fact:

```
$.arr?.max()    → { $max: "$arr" }                                      (a $cond test before)
$.o?.keys()     → { $map: { input: { $objectToArray: "$o" }, as: "jsmqlKv", in: "$$jsmqlKv.k" } }
$.o?.a.keys()   → the $cond test stays: under the dot, .keys() runs on {} and gives []
```

The rows `keys`, `values`, `entries`, `fromEntries`, `max`, `min`, `round`, `ceil` and
`floor` state the fact. A table in
[test/compiler-methods.test.ts](../../test/compiler-methods.test.ts) measures each row
over a missing receiver and over a `null` receiver. A row that reads a missing receiver
as a value (`nullReceiverAs`) cannot state the fact, and the `NullAnswer` type refuses
the pair. The `.assign()` row does not state it, because `$mergeObjects` gives the other
operands for a `null` receiver, not `null`.

## 2026-10-17 — docs: HR5 states the number rule

HR5 gave the dot and `?.` answers for an array, an object and a string, but not for a
number. The developer's reading of the dot rule is "a dot gives the safe value, as
lodash does". [docs/LANG_RULES.md](../LANG_RULES.md) now states the dot rule for a number. A
number method on a missing or `null` receiver gives the safe value where one exists,
and `null` where none exists. `.clamp()` gives its lower bound, `.inRange()` gives
`false`, and `.range()` gives `[]`. The arithmetic methods, for example `.round()`,
have no safe value, so they give `null`. The mongod server gave these answers for `{}`:

```
$.n.clamp(0, 9)     → { $min: [{ $max: ["$n", 0] }, 9] }   → 0
$.n.round(2)        → { $round: ["$n", 2] }                → null
$.n?.clamp(0, 9)    → a $cond null test                    → null
```

The rule changes no MQL. It records the behaviour that the number rows already have,
before the `Math` members move onto the number receiver.
