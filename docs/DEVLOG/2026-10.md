## 2026-10-01 — feat!: the value-taking `Math` members move onto the number

JSMQL spelled each numeric operation two ways: a `Math` static (`Math.abs($.x)`) and,
for some of them, a number method (`$.x.round()`). One capability gets one spelling,
and the shorter spelling wins. JSMQL refuses every `Math` member that takes a value,
and its refusal names the method that emits the identical MQL. `Math` keeps the three
members that take no value: `Math.random()`, `Math.PI` and `Math.E`.

```
$.delta.abs()         // { $abs: "$delta" }
Math.abs($.delta)     // ✗ names $.delta.abs()
[$.a, $.b].max()      // { $max: ["$a", "$b"] }
$.x ** 2              // { $pow: ["$x", 2] }      — Math.pow is refused, and names **
$.raw.trunc(2)        // { $trunc: ["$raw", 2] }
$.x.log(10)           // { $log10: "$x" }         — .log(b) takes a base
```

Each moved row is on the number family and on `Math`. The number cell emits the old
lowering with the receiver as the first operand, and the `Math` cell refuses. The name
is unique to the number family, so an unproven receiver such as `$.delta` takes the
number rule. The developer also decided that a bare `Math` member is not a callback:
JSMQL refuses `.map(Math.floor)`, and the arrow `.map(x => x.floor())` is the one spelling.
The `.reduce` wrap reads `[acc, d.x].max()` as `$max`, and the update document reads
`$.n = [$.n, 5].min()` as `$min`, where both read `Math.max(…)` / `Math.min(…)` before.

Several number shapes are shorter. `.round()` takes the one-operand form
`{ $round: "$n" }`. `.floor(p)` and `.ceil(p)` fold the scale `10 ** p` for a constant
integer `p`, and `.cbrt()` folds `1 / 3`. `.sign()` is
`{ $multiply: [{ $cmp: [x, 0] }, { $pow: [x, 0] }] }`: the `$pow` factor is 1 for a
number and null for nothing, so a missing receiver gives null with no `$cond`. Every
number row whose operator answers null for a missing operand states `passesNull`.
`.max()` and `.min()` state it too. So `$.n?.round()` is `{ $round: "$n" }`. `$.b?.c ** 2`
drops its `$ifNull`, because `$pow` answers null on its own. `.clamp()`, `.inRange()`
and `.range()` keep their safe dot answers and their `?.` test. Each moved method, the
two folded scales and `.sign()` on a missing field run on the project's mongod in
test/compiler-methods.test.ts, against JavaScript's own answer.

## 2026-10-01 — feat!: the `Object` statics give way to the object methods

JSMQL had two spellings for each object reading: a static (`Object.keys(o)`) and a
method (`o.keys()`). Both emitted the same MQL. The developer decided that one
capability gets one spelling, and the shorter spelling wins. So `Object.keys`,
`Object.values`, `Object.entries`, `Object.fromEntries` and `Object.assign` are
refused. Each name still parses, and its refusal names the method that emits the
identical MQL, as `Object.groupBy` already did:

```
$.doc.keys()                // { $map: { input: { $objectToArray: { $ifNull: ["$doc", {}] } }, in: "$$this.k" } }
Object.keys($.doc)          // ✗ names $.doc.keys()
({}).assign($.docs)         // { $mergeObjects: "$docs" }
Object.assign(...$.docs)    // ✗ names ({}).assign($.docs)
```

`({}).assign(list)` is the one spelling that merges an array of objects. It was a
server error before: the cell emitted `{ $mergeObjects: [{}, "$docs"] }`, and the
server refuses an array among two or more operands. An empty-object receiver now adds
nothing, and one source takes the one-operand form. `$.a.assign(...$.docs)` dropped the
spread before; it now emits `{ $mergeObjects: { $concatArrays: [["$a"], "$docs"] } }`.
A statement of `Object.assign(target, …)` wrote into its target. That reading is gone,
together with the `mutatesArgumentAt` row fact and its desugar rule. A merge into a
field is now the assignment of a spread, `$.f = { ...$.f, ...x };`, and the refusal
names it.

The pair readers are shorter. Their `$map` body is fixed compiler text, so it reads
`$$this` and states no `as`. `.fromEntries()` reads the key with `$first`. A new row
fact, `passesNull`, says that the bare cell answers `null` for a missing receiver. Where
a `?.` stands directly before such a call, the compiler emits no `$cond`:
`$.o?.keys()` is `{ $map: { input: { $objectToArray: "$o" }, in: "$$this.k" } }`. The
constant folds of the five statics moved onto the methods, and a near-miss suggestion
never names a refused static. Each `.assign()` form and each `passesNull` row runs on
the project's mongod in test/compiler-methods.test.ts.

## 2026-10-01 — docs: HR5 states the answer of a number method on a missing receiver

HR5 stated the dot and the `?.` answers for an array, an object and a string method,
and said nothing about a number method. It now has one more clause. A number has no
empty value to run on, but the dot still gives a safe answer when the method has one:
`.range()` and `.rangeRight()` read a missing receiver as `0`, `.clamp()` gives the
lower bound, and `.inRange()` gives `false`. A number method with no safe answer gives
`null` in both spellings, as a string method does. `.round()` is the example.

The developer stated the intent of the rule. A dot gives a safe value, as lodash does,
for every kind of receiver, wherever a safe value exists. The four rows above keep the
answers that the developer chose for them. This clause is the base for the move of the
`Math` members onto the number receiver. On a row with no safe answer, `.` and `?.` give
the same MQL, so the row needs no `$cond` guard.
