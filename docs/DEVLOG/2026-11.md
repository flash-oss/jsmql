## 2026-11-06 — test: the JSMQL sources write Date(…) and the BSON constructors without new

The test suites now write a date as `Date(…)` and a BSON constant as `ObjectId(…)`,
`Long(…)` and so on, without `new`, in each JSMQL source. A JSMQL source is a string or a
template literal that a test passes to `jsmql(…)` or to a helper over it, or the body of an
arrow-form input. The two spellings give the same MQL, so no expected value changed:

```
$.t > Date("2026-01-01")        // → { t: { $gt: new Date("2026-01-01T00:00:00.000Z") } }
```

The expected values, the printed MQL, the harness code and the `${…}` values keep `new`,
because they are JavaScript, not JSMQL. The tests that check the `new` spelling itself stay
as they are. The next language change converts them.

## 2026-11-06 — fix: a method after a field read of a joined document compiles

The join road refused a method that came after a field read or an index read of the
joined value. The compiler peeled only the field reads at the end of the chain. The compiler
kept a method after such a read in the chain proper. The chain reader then found a
field read where it expects a method or `$$$.<coll>`.

```js
$ = { kyc: $$$.kycs.find({ _id: $.vanId }).nameDetails.pick(["firstName", "lastName"]) };  // refused before
```

Now the chain proper is the run of method calls directly on `$$$.<coll>`. Everything after
the first read is a value over the joined slot. A stream method after such a read, for example
`.filter(p)[0].aggregate(…)`, now gets the refusal of a stream method on a value. Before, it got
the general refusal of a join chain. See
[src/compiler/emit/join.ts](../../src/compiler/emit/join.ts) `lookupOf` and
[docs/specs/emit-pass.md](../specs/emit-pass.md) § The join road. The cases are in
[test/compiler-join.test.ts](../../test/compiler-join.test.ts).

## 2026-11-02 — chore: merge master: the index iteratee, one kind wording and the integer date parts

The developer asked for the local master to merge into this branch. The rule for this
branch is that its own work wins where the two versions conflict. Master brought these changes:

- the index form of an iteratee (`.keyBy(5)`)
- one wording for each refusal of a wrong kind
- the null refusal of a callback slot
- the line and column in a thrown error
- the refusal of a proven date in arithmetic
- the refusal of a fraction in each part of `new Date(…)`

All six stay.

These decisions of this branch take precedence over master:

- A type name over a value of the document stays refused, and the refusal names the
  method of the value. Master converts the value (`Long($.n)` → `$toLong`,
  `new Date($.ms)` → `$toDate` of `$toLong`). The merge keeps the refusal, and the tests
  of master that assert a conversion now assert the refusal or the method form.
- A BSON type name over a constant of its own type stays refused, and so does a boolean.
  Master converts both on the server (`Long(Long("5"))`, `Long(true)`). The merge removes
  `ownValue` and the `"bool"` kind of each numeric row. The kind check of a constant
  stays: `new Date(null)` and `new Date(true)` get the wording of a wrong kind.
- The fraction hint names `'<number>.ceil()'` and `'<number>.floor()'`.
- `.has(null)` in a query clause keeps the `$elemMatch` form of this branch, so a missing
  array does not match. Master's test of a written `[1, null]` now expects this form.
- A date method reads a missing date as the epoch. The claims of master's new date
  examples in docs/LANGUAGE.md show the `$ifNull` of the epoch.

```
Long(true)                         // ✗ a constant takes a string or a number
Long($.n)                          // ✗ the refusal names '$.x.toLong()'
new Date(1.5)                      // ✗ a millisecond count is an integer
$.a = [1, null]; $match($.a.has(null));
                                   // [{ $set: { a: [1, null] } }, { $match: { a: { $elemMatch: { $eq: null } } } }]
$.d.startOf("day").plus(1, "day")  // { $dateAdd: { startDate: { $dateTrunc: { date: { $ifNull: ["$d", new Date("1970-01-01T00:00:00.000Z")] }, unit: "day" } }, unit: "day", amount: 1 } }
```

docs/LANGUAGE.md § Date Operations no longer says that `new Date(x)` converts a number
through a long. It names `$.ms.toLong().toDate()` for a count of milliseconds.
