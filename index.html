Write MongoDB queries in JavaScript

JSMQL is a strict subset of JavaScript that compiles to MongoDB MQL JSON. Filters, aggregation pipelines, expressions and updates — in the syntax you already know.

MongoDB 8.0 deprecated server-side JavaScript through $function, $accumulator and $where. JSMQL is the replacement: it compiles ahead of time to native MQL, so the server runs ordinary operators. Nothing is evaluated as JavaScript at query time, and indexes still apply.

Pipeline Stages are statements

Pipeline A recommendation engine, in one query

Collaborative filtering end to end: narrow to the signed-in user, assert the match is unique, collect what they bought, tally what co-buyers bought that they do not own, then join the product documents and emit the top ten by score. Every scan of the large collections is recency-sorted and capped, so the work stays bounded.

JSMQL
const userId = 0x507f1f77bcf86cd799439011;
$$.filter({ _id: userId });
assert($$.length === 1, "More than one user with such ID found");

const myProductIds = $$$.orders
  .filter({ userId })
  .toSorted({ createdAt: -1 })
  .take(10)
  .map("productIds")
  .flatten()
  .uniq();

const candidateProductIdCounts = $$$.orders
  .filter(o => o.productIds.some(p => myProductIds.includes(p)))
  .toSorted({ createdAt: -1 })
  .take(100) // co-purchase orders, recent, capped
  .map("productIds")
  .flatten()
  .filter(p => !myProductIds.includes(p))
  .countBy(); // { ID: count } map
const candidateProductIds = Object.keys(candidateProductIdCounts).map(ObjectId);

const candidateProducts = $$$.products
  .filter(pr => pr._id in candidateProductIds)
  .take(500);

$ = candidateProductIds
  .map(id => ({
    productId: id,
    score: candidateProductIdCounts[id],
    name:  candidateProducts.find({ _id: id }).name,
  }))
  .orderBy({ score: -1 })
  .take(10);

Why JSMQL

MQL is a fine thing for a machine to read and an awkward thing for a person to write. JSMQL keeps the output — it is still MQL, and still the same MQL for the same input — and changes only what you type.

Your editor already understands it

It is JavaScript syntax, so highlighting, bracket matching and formatting work with no plugin. Import @koresar/jsmql/ops and the MongoDB operators autocomplete as well.

Indexes keep working

A comparison against a field lowers to a query document, not to $expr. JSMQL reaches for $expr only when the query genuinely needs server-side evaluation.

Errors tell you what to write

An unsupported construct is rejected with the JavaScript form that does work, and a misspelled method is met with the closest name. Every error carries a source position.

Parameters bind once

jsmql.compile() parses a parameterised arrow once and returns a function that binds arguments per call. The output stays a literal document, so it stays index-friendly.

Values interpolate safely

The jsmql`` template tag places runtime values as literals rather than as source text, so a value can never be read as syntax.

Drop it in where you are

Use the library, the mongoose plugin, or the jsmql command line, which reads source and writes MQL JSON the way jq does.
